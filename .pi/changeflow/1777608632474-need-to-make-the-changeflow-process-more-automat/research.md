# Research: need to make the changeflow process more automated, currently I the user have to run the commands to manually advance the phases and then type "go" to get you to keep working. When this should be controlled by pi

- 2026-05-01T04:11:46.108Z [note] Relevant implementation is the project-local Pi extension at pi/extensions/changeflow/index.ts, installed into ~/.pi/agent/extensions via home.nix. It owns the workflow state machine, /changeflow commands, Changeflow tools, prompt injection, Plannotator events, and write-policy hooks.
- 2026-05-01T04:11:50.091Z [note] Current UX requires manual intervention because several phase prompts tell the model to use `/changeflow advance ...`, but slash commands are only user/command inputs; the model cannot reliably execute extension commands as tools. Existing tools only auto-transition for high-level plan submission (HIGH_LEVEL_PLAN_SUBMITTED) and detailed plan submission (DETAILED_PLAN_SUBMITTED). Research completion, execution ordering, execution completion, QA completion, and final validation still depend on /changeflow advance or human messages.
- 2026-05-01T04:11:53.215Z [note] Pi provides pi.sendUserMessage(content, { deliverAs: 'followUp' }) for extensions to queue a real user message after the current agent run completes, and ctx.isIdle()/ctx.hasPendingMessages() for idle/queue awareness. Changeflow already uses pi.sendUserMessage(..., { deliverAs: 'followUp' }) after `/changeflow start` to kick off research automatically.
- 2026-05-01T04:11:57.176Z [note] A good automation pattern is to centralize phase transitions in a helper that calls transition(), updates status/persistence, and then queues the next phase prompt with pi.sendUserMessage(..., deliverAs: ctx.isIdle() ? undefined : 'followUp') or a safe wrapper. This avoids requiring the user to type 'go' after state changes.
- 2026-05-01T04:11:59.559Z [note] Need to avoid automation loops: after transitions that enter waiting states (high_level_user_review, detailed_user_review if added later, user_validation, done), Changeflow should not queue continuation. It should auto-continue only when entering agent-owned states such as high_level_planning, detailed_planning, execution_ordering, executing, and qa.
- 2026-05-01T04:12:03.230Z [note] Potential implementation options: add custom tools for lifecycle events (e.g. changeflow_complete_research, changeflow_define_execution_order, changeflow_complete_execution, changeflow_complete_qa) instead of instructing the model to call slash commands; or add a generic changeflow_advance tool. Phase prompts should reference tools, not /changeflow advance. The generic tool is smallest, but phase-specific tools have better affordances and validation.
- 2026-05-01T04:12:06.751Z [note] Plannotator review approval already transitions from high_level_user_review to detailed_planning in the pi.events review-result handler, but it currently only notifies. To remove the need for the user to type 'go', that handler should queue a follow-up message for the newly entered detailed_planning state when approved (and for high_level_revision when rejected).
- 2026-05-01T04:12:08.988Z [decision] Sufficient context exists to plan an MVP automation change: keep human review gates explicit, but make all agent-owned phase completions tool-driven and have Pi queue the next phase automatically after successful transitions.
