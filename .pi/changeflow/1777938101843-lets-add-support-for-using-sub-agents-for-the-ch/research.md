- 2026-05-04T23:42:58.742Z [note] Official subagent example: Pi ships `examples/extensions/subagent/`. It registers a `subagent` tool and invokes child agents by spawning separate `pi --mode json -p --no-session` processes. Agent definitions are Markdown with frontmatter in `~/.pi/agent/agents/*.md` and optionally `.pi/agents/*.md`; fields include name, description, tools, model. It supports single, parallel (max 8 tasks, max 4 concurrent), and chain modes with `{previous}` substitution. It streams child JSON events into parent tool updates, aggregates messages/usage/cost, propagates abort by killing child process, and confirms before running project-local agents. This is simple and proven but subprocess-based and not tightly integrated with Changeflow state.
- 2026-05-04T23:43:03.351Z [note] Subprocess/JSON-mode approach pros/cons for Changeflow: Pros: strong context isolation, easy per-agent tool/model limits (`--tools`, `--model`), no SDK lifecycle complexity, can stream progress by parsing JSON lines, can run multiple agents concurrently, and child processes cannot mutate parent in-memory state unless given a bridge. Cons: duplicated Pi startup overhead, harder state sharing, no direct typed access to child `AgentSession`, must carefully pass system prompts/tasks via temp files, must parse events and manage stdout/stderr, and child edits in the same working tree can conflict unless sequential or isolated by worktrees.
- 2026-05-04T23:43:08.611Z [note] SDK/in-process approach: Changeflow could create child `AgentSession`s directly with `createAgentSession({ cwd, model, tools: createReadOnlyTools(cwd) or createCodingTools(cwd), sessionManager: SessionManager.inMemory() or dedicated persistent dir, resourceLoader })`. This offers type-safe event subscriptions, direct messages/state, shared auth/model registry, lower process overhead, and easier custom tool/resource injection. Risks: extension code would be embedding full agent loops inside a tool/event handler; care is needed to avoid stale extension contexts, cancellation, compaction/retry behavior, session naming, and exposing parent-only Changeflow tools to children. For multi-session replacement docs warn subscriptions are session-bound and replacement requires rebinding extensions; child sessions should probably be in-memory or explicitly separate.
